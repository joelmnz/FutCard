# DOX — FutCard

AGENTS.md files are binding work contracts for their subtrees. Follow the nearest applicable AGENTS.md plus every parent above it when editing.

## Purpose

FutCard is a client-side football card trading game for children: onboard a manager, open packs, manage a collection, trade and sell, play matches, and grow club value. It runs entirely in the browser with no backend; saves live in `localStorage`, and the hosted save is separate from `localhost` saves. Deployed to GitHub Pages as a static build.

## Ownership

- `index.ts` — local Bun static server on port 5065 serving `src/` and `public/`; GET/HEAD only with path sanitization. Owned here.
- `src/` — the browser app, owned here: `index.html` (shell; loads `data/` scripts, then `teams-model.js` and `teams-ui.js`, then `app.js`), `app.js` (game state, persistence and existing game flows; consumes classic-script globals), `teams-model.js` (DOM-free formation/assignment/normalization rules), `teams-ui.js` (library, draft editor and placement interactions), `data/roster.js` (dated 2026/27 curated player roster snapshot with verification sources in `docs/roster-2026-27.md`; nations stored as plain names), `data/reference.js` (legacy identity pools, position weights, nation-to-flag-code map), `site.css`, `sw.js` (service worker template with build placeholders), `manifest.webmanifest`.
- `public/` — static assets copied to the site root (`favicon.svg`, `icons/`); SVG placeholders regenerated by `scripts/generate-icons.ts`. Owned here.
- `scripts/` — build pipeline, icon generation, and build tests. See [scripts/AGENTS.md](scripts/AGENTS.md).
- `game.test.js` — Bun test that loads `src/data/*.js` then `src/app.js` in a stubbed-browser VM (test hook at the end of `app.js`) and asserts roster integrity, generation flows, save roundtrip, offline purity, and source hygiene (no flag glyphs or hidden/bidirectional Unicode in shippable source). Owned here.
- `docs/` — product and implementation documents, owned here. `SPEC.md` describes an earlier planned Svelte/Vite/IndexedDB stack; the implemented app is plain JavaScript with `localStorage`. Treat code as the source of truth. `roster-2026-27.md` is the dated verification evidence for the player roster snapshot.
- `.github/workflows/deploy.yml` — Pages deployment workflow, owned here.

## Work Guidance

- Bun-first workflow: `bun run dev`, `bun run check`, `bun run build`, `bun test`.
- Type checking (`bun run check`, `tsc --noEmit`): strict TS applies to `index.ts` and `scripts/*.ts`. `src/*.js` files are part of the program for inference (`allowJs`, no explicit `include`) but are not type-checked (`checkJs` is off) — including more JavaScript under type checking is a `tsconfig.json` change, not automatic. Verify game changes in the browser, not through `check`.
- Keep the app 100% client-side with relative asset paths so it works from the GitHub Pages project subpath. Do not add a backend, framework, or dependencies here.
- Data scripts in `src/data/` are classic scripts (no bundler): top-level `const`s become page globals consumed by `app.js`. When adding a data file, list it in `src/index.html` and in `scripts/build-static.ts` (fingerprint, precache, version) so offline caching stays correct.
- Source hygiene: never commit flag emoji, tag characters (U+E0000-U+E007F), variation selectors, zero-width or bidirectional Unicode. Nations are plain names in data; card flags are derived at render time from `NATION_FLAG_CODES`. The `game.test.js` source-hygiene test enforces this.
- `src/sw.js` is a template: the build replaces `__FUTCARD_SW_VERSION__` and `__FUTCARD_PRECACHE_URLS__`. Never commit resolved values into source.
- Do not change gameplay, the save schema, the deployment workflow, or dependencies as part of documentation work.
- Deployment: `.github/workflows/deploy.yml` runs check, test, and build, then publishes `dist/` on push to `main` or manual `workflow_dispatch`. The repository default branch is `master`, and the workflow trigger branch is `main`, so pushes to `master` do not auto-deploy — deploy via a `main` push or a manual run.

## Goalkeeper contracts

- Goalkeepers use the existing five-stat card schema with defense-led `OVR_WEIGHTS.GK`; do not introduce separate goalkeeper stats without an explicit schema change. Preserve legacy saved card stats, overall ratings and prices rather than recalculating them from current roster rules.

## Teams contracts

- Keep `TeamsModel` DOM-free. `TeamsUI` receives collection/team access, ID allocation, persistence, card rendering and notifications through `init`; do not couple it directly to `app.js` state.
- Edit detached drafts. Failed saves and deletions restore the saved team library; report success only after persistence succeeds.
- Preserve the drag-source DOM during `dragstart`; replacing it can cancel native browser dragging. Retain click/keyboard placement as an alternative to dragging.
- Teams use eleven fixed 4-3-3 slots and reference owned card IDs; any natural position may fill any slot without penalties. Card instances are unique within a team but reusable across teams.
- Saves use version 2 under the existing `futcard-save-v1` key; version 1 saves migrate to an empty team library. Teams and independent team IDs persist; drafts/search/drag state do not.
- Selling or trading away a card clears its assignments via the shared ownership-removal hook. Teams never consume cards.
- `teams.test.js`, `teams-ui.test.js`, and `teams-integration.test.js` cover model rules, UI flows and persistence/ownership integration.
- New classic-script modules must be loaded before `app.js` and fingerprinted, versioned and precached by the static build.

## Verification

- `bun run check` — TypeScript project checks (`tsc --noEmit`); reports errors in `index.ts` and `scripts/*.ts`, includes `src/*.js` for inference without type-checking them (`checkJs` off).
- `bun test` — builds `dist/` and asserts the Pages artifact shape (fingerprinted assets incl. `data/` scripts, resolved service-worker placeholders, `.nojekyll`), and runs `game.test.js`: roster integrity (verified clubs/positions/nations, overall/rarity/price derivation, goalkeeper coverage), generation across starter/pack/market/bot, save roundtrip incl. legacy v1 and goalkeeper cards, offline purity (no network calls in `app.js`), and source hygiene (no hidden/bidirectional Unicode).
- `bun run build` — produces the static `dist/` for Pages.
- Documentation-only changes have no dedicated check; verify statements against the referenced files and commands instead.
